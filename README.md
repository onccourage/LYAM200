# CQA — Conversation Quality Analytics (Freedom Broker Hackathon)

Прототип оценки качества работы операторов поддержки по диалогам (чаты и звонки, RU / KZ / EN).
LLM только классифицирует ответы по критериям; баллы считает детерминированный `scoring.py`.
**Чек-лист — это данные**: критерии, веса, шкалы и тексты хранятся в JSON/БД и меняются через UI
без правки кода и перезапуска.

> Статус: этапы 1–4 — загрузка наборов, модели, сид чек-листа, ядро подсчёта, LLM-конвейер, UI (список и карточка).
> Остальные разделы README будут дописаны по мере этапов.

## Архитектура

```
API организаторов ──► dataset.py ──► data/cache/{group_id}.json + SQLite
                                         │
чек-лист (JSON, версии) ──► prompt_builder ─► llm ─► validator ─► scoring ─► evaluations
                                         │                               │
                                       web/ (HTML+JS, без сборщика) ◄── FastAPI
```

## Переменные окружения

См. `.env.example`. Главные: `ANTHROPIC_API_KEY`, `LLM_MODEL` (по умолчанию `claude-sonnet-5-5`),
`DATASET_API_URL`, `DEFAULT_GROUP_ID`, `EXPLANATION_LANG`, `LONG_PAUSE_SEC`, цены за токены.

## Загрузка набора

- UI/API: `POST /api/datasets/{group_id}/load` — запрос к API организаторов идёт только с бэкенда.
  Ответ кэшируется в `data/cache/{group_id}.json`; при недоступности API берётся кэш (с предупреждением).
  `isSuccess=false` показывается как ошибка, кэшем не маскируется.
- CLI: `make fetch GROUP=DEV`.
- Ручная загрузка: `POST /api/conversations/upload` (JSON-файл: запись, массив записей или ответ API).
- Исходные `timestamp` не изменяются; добавляется `offset_sec` (чаты `MM:SS`/`HH:MM:SS`, звонки —
  ISO 8601 от первой реплики; базовая точка — `dataset.call_base_time`).

## Чек-лист

Сид: `data/checklists/default_chat_v1.json` (загружается в БД при первом старте).
Сохранение изменённого чек-листа (`POST /api/checklists`) создаёт новую неизменяемую версию.
`POST /api/checklists/validate` — проверка без сохранения + предупреждения (сумма весов ≠ 100 и т.п.).

## Подсчёт баллов (`app/scoring.py`)

Чистая функция `score(checklist, answers, channel)`, только `Decimal`:
- binary: «Да» = вес, «Нет» = 0; scale: `вес × ступень / max(ступеней)`; flag — 0 баллов, отдельный `gross_error`.
- N/A (только при `na_allowed`) и критерии не своего канала исключаются, итог нормируется:
  `total = Σ баллов / Σ применимых весов × 100`; у каждого критерия видны `effective_weight/points`.
- Округление `ROUND_HALF_UP` только итога и итогов секций (знаков — `rounding` чек-листа).
- Нет применимых весов → `total = null` («не рассчитывается»), не 0. Грубая ошибка итог не обнуляет.
- Неверный ответ (N/A без разрешения, ступень не из шкалы, неверный тип) → `ScoringError`.
- `answer = null` — критерий на ручной проверке: в расчёт не входит, итог помечен `is_partial`.

## LLM-конвейер

`preprocess → prompt_builder → llm → validator → scoring → evaluations`:
- **preprocess**: реплики `m0…mN` (ID = индекс), факты: первая реплика оператора (не бота), язык клиента
  по его репликам, паузы ожидания ≥ `LONG_PAUSE_SEC`, системные события, канал/аудио.
- **prompt_builder**: неизменная рамка (`PROMPT_VERSION`) + блок критериев и JSON-схема ответа,
  сгенерированные из чек-листа. Вес в промпт не передаётся. Транскрипт — внутри `<transcript>`, как данные.
- **llm**: `LLMProvider` (Anthropic / OpenAI-совместимый endpoint / Fake для тестов). Ответ строго по
  JSON-схеме через structured outputs (`output_config.format`).
- **validator**: ответ допустим для типа, N/A только при разрешении, `message_id` существует, цитата —
  подстрока реплики, положительный ответ подкреплён репликой оператора/системы, «Нет» без цитат — с
  `checked_range`, N/A — с `na_reason`. Ошибка → один повтор только по ошибочным критериям → `needs_review`.
- **кэш критериев**: `hash(транскрипт) + hash(критерий) + модель + PROMPT_VERSION`. При новой версии
  чек-листа в LLM уходят только изменённые критерии; смена веса — только пересчёт.
- **requires_audio**: без аудио → N/A «нет аудиозаписи» (если разрешён), со звуком → `needs_review`.

Прогон из консоли:

```bash
python scripts/run_eval.py DEV                 # 5 диалогов разных каналов/языков
```

```bash
python scripts/run_eval.py DEV p1-ru-001 --dry-run   # показать промпт без вызова модели
```

API: `POST /api/evaluations/{group_id}/{conversation_id}?full=false`, `GET` того же пути, `GET /api/datasets/{group_id}/evaluations`.

## Интерфейс

`http://localhost:8000` — чистые HTML/CSS/JS (ES-модули), без сборщика и CDN, отдаётся самим FastAPI.
- **Наборы и диалоги** (`#/d/{group_id}`): ввод `group_id` → «Загрузить набор», ручная загрузка JSON,
  список с фильтрами (канал, язык, статус оценки, грубая ошибка, поиск) и итоговым баллом.
- **Карточка диалога** (`#/c/{group_id}/{conversation_id}/m5`): слева транскрипт с якорями `m0…`
  (бот и система приглушены), справа итог, секции, бейдж грубой ошибки, версия чек-листа, модель, стоимость;
  по каждому критерию — ответ/ступень, баллы, исходный и эффективный вес, обоснование, доказательства.
  Клик по доказательству прокручивает к реплике и подсвечивает её; для «Нет» подсвечивается проверенный
  диапазон; для N/A показана причина; низкая уверенность и `needs_review` выделены.
  Для звонков — `<audio>`: клик по доказательству перематывает на `offset_sec` и запускает запись;
  если встроить нельзя — кнопка «Открыть запись» с тайм-кодом.
- Кнопки «Переоценить текущей версией» (неизменённые критерии из кэша) и «Переоценить полностью».
- Встраивание (Dynamics 365): `window.CQA_CONFIG = { API_BASE_URL: "https://..." }` или `?api=https://...`;
  все пути к статике относительные. Светлая/тёмная тема, адаптивная вёрстка.

## Модель и стоимость

По умолчанию `claude-sonnet-5-5` (вход $2 / выход $10 за 1 млн токенов; дешёвый режим — `claude-haiku-5-5`, $0.10 / $0.50).
Особенности текущих моделей Claude, учтённые в коде:
- принудительный `tool_choice` и `temperature` на них возвращают 400, поэтому схема ответа гарантируется
  structured outputs; детерминизм обеспечивает схема + валидатор + кэш, а не `temperature=0`;
- глубина рассуждений — `LLM_EFFORT` (по умолчанию `medium`);
- при отказе классификатора безопасности включён серверный fallback (`LLM_SERVER_FALLBACK=auto`, beta
  `server-side-fallback-2026-07-01`); отказ без fallback → критерии `needs_review`;
- рамка + критерии кэшируются (prompt caching), стоимость считается с учётом кэша по ценам из `.env`.
